# Stage 2.2 — timeline thumbnail architecture investigation

Research date: 2026-10-20. Target: VLC 3.0.24, Qt desktop interface, Windows x64. This document proposes changes; none of its classes, protocol messages or thumbnail functionality is implemented.

The repository owner reports that the official baseline was cross-compiled with WSL2, Docker Desktop and the official Windows x64 image, then launched and tested successfully on Windows. That supersedes the earlier cloud-build blocker as the project's baseline status. This research session did not reproduce that build, inspect its binary, or run device tests. The older reports remain historical records of their own cloud attempts.

Inspected source: release `6de05adcbaf2e8b85fe86aad4169393098628119`, with documentation through `aed5f1bcdcb17af7c4246ae8f8452a8b1aa2d65e`. Tracked files outside `docs/` match the release. The Stage 2.2 branch starts from `feature/stage-1-vlc-3.0.24`; the validated baseline is not changed or merged into.

## Decision

Recommend an **isolated, short-lived helper process using this build's LibVLC 3.0.24**, with a separate instance, media descriptor and player for each uncached extraction. A GUI-owned service debounces hover requests, maintains a bounded cache and supervises at most one helper. The helper uses LibVLC memory-video callbacks to return a small image. Existing `TimeTooltip` remains the native Qt presentation surface; text/chapter behavior remains the fallback.

This minimizes coupling to VLC input/vout internals, avoids adding a public LibVLC dependency to the already loaded Qt plugin, and makes a blocked decoder or synchronous stop independently terminable. It adds a small executable and IPC/packaging work, but provides a stronger failure boundary than a worker thread inside the playing application. It is process isolation, not a security sandbox and not a guarantee against shared CPU/disk contention.

**Timing is the release gate:** this version's public memory callbacks provide no frame PTS or seek-completion token. The APIs support extracting pixels from an independent player positioned near a requested time; they do not by themselves prove those pixels are the exact requested frame. The first prototype must establish acceptable approximate preview accuracy on timestamped MP4/MKV fixtures. If it cannot, retain text-only behavior and reconsider a timestamp-aware backend before implementing the UI. Do not hide this limitation behind a `TimeChanged` event or a fixed sleep.

Initial scope: seekable, finite-duration regular local `.mp4` and `.mkv` files, with a usable video track. No network streams, devices, playlists, optical-disc navigation or arbitrary inherited input options. An extension is an eligibility hint, not proof of codec support. Playback controls and foreground player state are never part of the extraction interface.

Windows taskbar thumbnail code (`main_interface_win32.cpp`) describes the current window/video, not arbitrary-time extraction.

## Alternatives and tradeoffs

| Approach | Why it is realistic | Decision |
| --- | --- | --- |
| Helper process with private LibVLC memory output | Existing player, codec and vmem APIs; termination boundary around decoding | Recommended initial backend. Costs cold-start latency and another portable executable. Accuracy remains a prototype gate. |
| In-process private LibVLC player on a worker thread | Same pixel APIs without IPC | Defer. `lib/media_player.c::release_input_thread` calls `input_Stop` and `input_Close`; a stalled join can outlive cancellation. Re-entrant engine initialization, Qt-plugin linkage and shutdown would affect the application process. |
| Separate internal `input_thread_t` and private output | Qt already uses internal libvlccore facilities | Defer. Never pass the foreground `input_resource_t` or renderer. Direct callback-address variables used by vmem are internal plumbing; reproducing them couples the UI to more internals than public LibVLC in a helper. A new vout must also handle VLC clock semantics. |
| Dedicated FFmpeg decoder in helper | Existing contrib uses FFmpeg 8.1.2; `modules/demux/avformat/demux.c` uses `av_seek_frame`; `modules/codec/avcodec/video.c` uses `avcodec_send_packet` / `avcodec_receive_frame` | Second choice if measured LibVLC accuracy fails. Explicit packet/frame timestamps can permit decode-forward selection, but require demux time-base, reorder, index, conversion and licensing/linking work. Local FFmpeg headers/libraries and a standalone helper link were not compiled or verified in this session. No external ffmpeg.exe dependency is assumed. |
| Image helper / scene filter | `include/vlc_image.h`: `image_HandlerCreate`, `image_Convert`; `modules/video_filter/scene.c` periodically writes decoded pictures | These convert/capture supplied pictures; they do not demux and seek an arbitrary movie timestamp. Scene filters on active playback change its pipeline and perform disk IO. Reject for hover extraction. |
| Foreground snapshot, temporary seek or decoder reuse | `libvlc_video_take_snapshot` and `vout_GetSnapshot` exist | Reject. They capture the current output, not arbitrary-time frames. Seeking and restoring would interrupt playback. `lib/video.c::libvlc_video_take_snapshot` also notes non-atomic parameters and cross-player callback concerns. |

A custom vout's `picture_t` timestamp is not automatically a media-file PTS: `src/input/decoder.c` uses `input_clock_ConvertTS`. Replacing public callbacks with a vout solely to read `picture->date` does not solve timestamp association without investigating the clock mapping.

## Source reuse and extraction transaction

“Reuse media” means reopening the same local file through the same build's plugins. It does **not** mean sharing the active input, file position, demux, decoder, playlist, video output, audio output or state variables.

1. On current-input change, increment a media generation immediately, clear each view's image, invalidate pending work, and snapshot an owned URI from `MainInputManager::currentInputItem()`. Copy no arbitrary item options (`input_item_CopyOptions` exists but is deliberately not used). Retaining an item merely extends lifetime; it does not make all mutable fields thread-safe.
2. Move path canonicalization/stat/regular-file checks off the GUI thread. Safely interpret a file URI, preserve UTF-8/Unicode and escaping, and reject network/UNC/device schemes. Do not reinterpret `#`, `%`, spaces or a leading dash through shell expansion. Mapped drives can still be remote; resource timeouts remain necessary.
3. Spawn the bundled helper via an absolute executable path and argument list, never a shell command. Pass the source URI and request through stdin IPC, not interpolated command-line options. A fresh helper accepts one extraction then exits. No playlist or Qt interface is created in it.
4. Create the private instance with the option policy above, new media, then player. Register format/video callbacks and required events before play. Request the bucket's startup time with `:start-time`, serialized with a locale-independent decimal separator. Avoid float rounding assumptions on long durations; the source itself uses float seconds here.
5. Negotiate a bounded output size/pixel layout; play and wait for private output with a deadline. A startup seek is asynchronous: do not simply cache the first callback as the target. Suppress startup/stale candidates using private state notifications, but regard `get_time`/`TimeChanged` only as supporting clock evidence. Copy a bounded candidate at display delivery, not an unlocked buffer that may never be displayed. The fixture experiment must validate the selection rule. If uncertain, return a miss rather than an unrelated beginning-of-file image.
6. Send at most one owned image result with request identity and diagnostic clock estimate; stop/release from helper control context, not a VLC callback. Exit after cleanup. The GUI may accept a valid result before process exit but must not start a replacement until the previous process has exited.

A fresh process/player per request avoids confusing pre-seek frames from a previous target. It does not prove accurate startup seeking. Do not optimize to player reuse until frame association, flush behavior and teardown have tests. Reopening the file supports ordinary local MP4/MKV with the baseline's codecs but does not promise subtitle/filter/selected-track parity. Initially choose the private default video track and document that choice; reject ambiguous multi-angle/navigation cases rather than copying active options blindly.

## Proposed classes, files and interfaces

These names are **new design proposals**, not existing VLC APIs.

| Proposed component / file | Responsibility |
| --- | --- |
| `gui/qt/util/thumbnail_preview.hpp/.cpp`: `ThumbnailPreviewService` | One service per Qt interface, shared by normal/fullscreen sliders; GUI-thread scheduling, current generation, one helper supervisor, result fan-out, cache accounting. Lifetime below the interface, above individual sliders. |
| same file: `ThumbnailPreviewSession` | Per-slider owner token, hover epoch/target and visibility subscription. Destroying a slider invalidates only that view; it cannot leave a raw widget callback alive. |
| `gui/qt/util/thumbnail_cache.hpp/.cpp`: `ThumbnailCache` | Byte-bounded LRU and bounded negative cache, no decoding and no widget references. Could remain private within the service initially to reduce file count. |
| `gui/qt/util/thumbnail_process.hpp/.cpp`: `ThumbnailProcessClient` | Asynchronous QProcess supervision, framed input/output validation and kill/reap state machine; metadata/image copy work handled by a worker QObject/QThread if it exceeds GUI budget. |
| `bin/thumbnail_helper.c` | Windows-only initial helper; public LibVLC APIs, standard C IO and bounded buffers, control-loop synchronization using the available Windows threading platform. No Qt GUI and no call to the active process. |
| `bin/thumbnail_protocol.h` | Small versioned, fixed-width protocol description shared with the Qt client; no VLC pointers or C struct ABI transmitted. |
| Existing `input_slider.*`, `timetooltip.*`, `components/controller.*` | Later minimal hover/session wiring and image presentation; all seek connections stay intact. These files are unchanged in this stage. |

Logical request: `(protocolVersion, mediaGeneration, sessionId, hoverEpoch, requestId, fileIdentity, targetMs, width, height, extractionPolicyVersion)`. Logical result: same identity plus `status`, dimensions, stride, pixel-format identifier, requested bucket time, optional **estimated** player time and bounded pixel payload. There is no `actualFramePts` field until a backend can truthfully provide it. These are protocol fields, not functions in VLC.

Use explicit length-prefixed binary framing over stdin/stdout, diagnostics separately on stderr. Limit input URI length, header size, dimensions, stride multiplication, payload and buffered partial reads before allocation; reject overflow, invalid versions, truncated frames and unsolicited extra results. Bound stderr too. No JSON/base64 expansion or temporary PNG files is needed. Windows pipes carrying pixels must use binary mode. Unit-test byte order and partial IO independently of decoder timing.

Helper location is anchored to the trusted portable application directory, not PATH or cwd. Package alongside `libvlc.dll`/`libvlccore.dll` and the matching `plugins/`; inspect the platform DLL-loading behavior before shipping. `src/win32/dirs.c::config_GetLibDir` and `src/modules/bank.c::AllocateAllPlugins` support library-relative plugin discovery and show that `VLC_PLUGIN_PATH` can add paths. Do not trust an inherited arbitrary plugin path; choose a controlled environment before `libvlc_new`, without mutating foreground process environment. Test startup from a different cwd and with another VLC installed.

## Threading, cancellation and media lifetime

- The GUI owns hover state and the small cache lookup, updates timestamp/chapter text immediately, and schedules work with a separate single-shot timer. Proposed initial debounce: 150 ms; a tunable starting value, not a measurement. Repeated movement within a time bucket does not restart decoding.
- Strict bounds: **one helper process and one latest pending request globally**; no worker or process per mouse move. Replacing a pending request overwrites it. When different sliders are active, the most recently hovered visible session wins; subscribers for the same cache key may share one result.
- On newer hover, invalidate the old result immediately. Cooperative cancellation asks helper control code to stop. Since `libvlc_media_player_stop` may block, a proposed 250 ms grace timer then terminates the helper; do not spawn its replacement until exit is observed. A separate proposed 3 s extraction deadline handles slow/broken files. Add restart-rate limiting/backoff so rapid motion or recurring failures cannot create a process storm. Never call blocking QProcess waits/destructors with a running child on the GUI thread.
- `lib/event.c::libvlc_event_send` invokes listeners while holding its event-manager lock. Event and video callbacks only copy small state / signal helper-owned synchronization; they must not stop, release, detach callbacks, write potentially blocking IPC, or call UI code. The helper control thread writes the result and owns teardown. Keep callback opaque data and negotiated buffers alive through player stop/release and in-flight callback completion. Format cleanup must not race an image copy.
- Video lock returns a buffer identity; unlock/display refer to it. Honor the documented pitch/line/alignment requirements and format renegotiation. Copy rows into an owned output buffer before allowing buffer reuse. Check allocation arithmetic, rotation/SAR, channel masks and alpha; `RV32` is not a promise of portable RGBA byte order. The vmem implementation applies video rotation. Prevent accidental double rotation in Qt.
- On leave/hide/input change, increment that view's hover epoch or the global media generation, hide/clear its image and invalidate pending display. Cached results may be retained by policy, but a late result must never re-show a hidden tooltip. Match generation, request/bucket, owner and hover visibility before applying it. Generation changes also protect two consecutive openings of the same URI.
- Stop/end/interface teardown cancels outstanding work. Pause alone does not disable a preview. Playlist replacement, source modification and track-policy changes invalidate source identity. Stop/reap the supervised process asynchronously on interface exit; a bounded shutdown design must be proven, including Windows child cleanup when the parent exits unexpectedly. A Windows Job Object is a possible future containment mechanism, **not verified or implemented by this research**.

## Cache policy and avoiding unnecessary work

Proposed starting policy: one-second nearest buckets for short/medium media, 240×135 maximum logical thumbnail with aspect preservation, a **32 MiB image-cache budget**, a 256-entry cap, one result per key, and no disk cache. Keep requested hover time distinct from extraction bucket time. Existing time text continues to show hover time; label an approximate preview with its bucket time so a cache hit is not misrepresented as frame-exact. Long-video coarser bucketing requires an explicitly reviewed tolerance; do not silently change precision to meet a latency target.

Key: normalized source identity (canonical path plus size/mtime and best available stable file identity), video-track policy, orientation/output size, bucket time and backend/policy version. Canonicalization and file metadata work are asynchronous; no file IO during mouse handling. Path+mtime is not content authentication: replacement with identical metadata remains a risk. Namespace cache entries by media generation initially if file identity is uncertain; stronger identity checks can be added later.

Cost includes owned QImage row stride × height and metadata. Account for returned pixels and transient image copies separately; cap each IPC frame at 1 MiB, the IPC receive buffer, in-flight images and queue slots. Do not make an additional permanent QPixmap cache that escapes the byte budget. A 32 MiB thumbnail cache does **not** bound LibVLC decode memory for 4K/8K files: monitor helper memory/time and fail closed on resource pressure. Decoder memory limits require device measurements and a supported process-limit strategy.

Lookup before scheduling; coalesce in-flight identical keys; cancel work for obsolete buckets; decode on demand only. No eager movie-wide scan or speculative prefetch initially. Cache `NoVideo`/unsupported/decode failures with a bounded 64-entry short-lived negative cache; confirmed audio-only status can last for that source generation. A transient timeout must not permanently label a file audio-only. LRU eviction applies across media to cap session-wide memory. Never cache private paths/frames persistently or log full URLs by default.

## Native Qt tooltip integration and behavior boundaries

The existing `SeekSlider::mouseMoveEvent` computes chapter text and `getValuePercentageFromXPos(event->x()) * inputLength`. `inputLength` is seconds, chapter points are microseconds; LibVLC target times are milliseconds. Use checked 64-bit conversions. Reuse the handle-aware coordinate mapping; reject zero/invalid duration and widgets no wider than the handle. Keep vertical sliders text-only initially because this source already has horizontal-only chapter/tooltip TODOs.

`components/controller.cpp` wires `positionUpdated → setPosition`, `sliderDragged → InputManager::sliderUpdate`, buffering, and `inputCanSeek → setSeekable`. `InputManager::sliderUpdate` writes active `position`; `SeekSlider` also maintains drag, click/chapter, wheel and 150 ms seek-limit behavior. Hover must emit a **new preview intent**, never those seek signals, setValue or foreground time/position writes. Prefer suppressing new preview jobs during active drag/mouse-button use; ordinary click/drag/wheel/chapter behavior stays unchanged. Do not reuse the seek timer for thumbnail debounce.

Add proposed `TimeTooltip::setPreviewImage(...)` / `clearPreviewImage()` operations on the GUI thread; these are not existing methods. Extend `paintEvent` to draw the image with QPainter and keep the existing text/chapter line. Extend `adjustPosition`/`buildPath` to include image dimensions. The current `setTip` only triggers geometry recalculation on target, time-string-length or chapter changes; image arrival, removal, scaling and DPI changes must trigger it explicitly. Decode/copy away from the GUI, deliver an owning QImage through a bounded queued notification, then schedule `update()`; never decode in `paintEvent`.

`TimeTooltip` is a parentless top-level widget owned/deleted by `SeekSlider`, with transparent mouse events and tooltip window flags. Do not steal focus or overlay click input. Inspect and preserve `enterEvent`, `leaveEvent`, `hideEvent`, tooltip event filtering, active-popup checks and slider destruction. Late image arrival cannot invoke `show()` or `raise()` without rechecking hover/visibility. Audio-only/unknown/error/cache-miss cases retain timestamp/chapter-only rendering without a placeholder that changes playback controls.

Fullscreen uses `FullscreenControllerWidget` in `components/controller.cpp` and can have another slider. Shared extraction/cache must not couple tooltip lifetime or coordinates between views. On fullscreen controller auto-hide, window movement, popup menus and source changes, clear that view. Position the larger tooltip within the current screen's available bounds; handle negative origins, screen gaps, mixed DPI and taskbars. `timetooltip.cpp` already guards old Qt `QDesktopWidget` versus newer `QScreen` paths: preserve Qt 5.6 compatibility and do not introduce unguarded Qt 5.10/6-only APIs. No cursor-to-thumbnail movement should trigger a seek or defeat controller auto-hide.

## Build-system/dependency impact (future implementation only)

- Add Qt sources/headers and corresponding `Q_OBJECT` MOC entries to `modules/gui/qt/Makefile.am` using its documented pattern; continue existing QtCore/Gui/Widgets dependencies. QTimer, QThread, QImage and QPainter are existing facilities; QProcess supervision must be compiled against the baseline's actual Qt version. No Qt Quick, web UI, image-download service or new codec dependency is needed for the recommended backend.
- Add a Windows helper executable target in `bin/Makefile.am`, linked to `../lib/libvlc.la` following existing executable patterns. Specify its Windows console/stdio behavior deliberately; do not blindly copy `vlc.exe`'s GUI entry-point flags. The helper uses public headers, not private libvlc object layouts. `lib/libvlc.sym` already exports the recommended public API; no new core export is proposed.
- Audit install/portable packaging in `extras/package/win32/package.mak`. `package-win-common` copies installed executables/libraries and plugin directories, but helper inclusion, stripping and correct dependency placement still need explicit verification. Maintain license/attribution and corresponding-source obligations.
- Verify vmem, MP4, MKV and required avcodec/conversion plugins exist in the tested portable package. Recipe presence is not artifact verification. Reuse the validated MinGW/CRT/image and rebuild only affected targets after configuration; no contrib/toolchain upgrade is proposed. A FFmpeg helper would need a separate dependency/link/licensing review if the timing gate rejects LibVLC.

## Unresolved questions and incremental implementation gates

1. **Accuracy experiment first:** implement only a helper-side proof of capture in a later authorized coding task. Test startup positioning on synthetic timecoded MP4/MKV, including VFR/B-frames, long GOPs and nonzero/edit-list timestamps. Establish which candidate-delivery rule is trustworthy; player clock events alone are insufficient. Proposed initial extraction error budget: ≤250 ms relative to the requested bucket on ordinary fixtures, plus ≤500 ms nearest-bucket error. Report misses separately. If this cannot be met reliably, stop and evaluate the verified FFmpeg primitives; do not ship stale frames.
2. **Isolation/lifetime prototype:** prove no private audible output/window, bounded callback buffers, stop/close behavior, timeout/kill/reap, corrupted-media failure and process-start throttling. Measure cold-start CPU/memory/latency before committing to per-request processes. Only then consider a reusable helper/player for speed.
3. **Service/cache without tooltip:** exercise one-active/one-pending invariants, media-generation invalidation, path/Unicode handling, bounded IPC and LRU. Use deterministic fake results to stress out-of-order completion and source replacement without decoding every test case.
4. **Minimal Qt presentation:** add one image area and preview-intent connections while preserving all existing seek paths; support local seekable video only and keep text fallback. Do not refactor playback/input-manager internals to make this convenient.
5. **Portable/device validation:** build and test the custom package on Windows x64 before enabling the feature by default. Diagnose any fidelity/latency/lifetime problem before widening formats or network scope.

Known risks: helper startup cost and antivirus scanning, decoder CPU/memory contention, synchronous file metadata on mapped drives, time rounding on very long files, inaccurate input indexes, actual-frame timestamp ambiguity, HDR/color/SAR/rotation differences, multi-track selection, child processes surviving abnormal parent exit, DLL/plugin search contamination, and Qt top-level tooltip behavior under fullscreen/mixed DPI. None is resolved by successful baseline playback alone. Source investigation is complete enough for the gated prototype; extraction accuracy, helper packaging and device performance remain unverified. No external research blocker prevented this document.

## Build and device-test acceptance criteria

A future implementation must meet all of these before release. These are **planned checks, not executed tests in Stage 2.2**:

- Clean Windows x64 cross-build with the validated image/contrib/CRT; helper and Qt plugin compile/link; no new core API or external codec executable; portable archive integrity, PE architecture and dependency inspection pass. Run from a clean directory without installed VLC providing DLLs, and from a non-package cwd.
- Same baseline smoke tests plus local H.264/H.265 MP4/MKV fixtures, VFR/B-frame/long-GOP content, Unicode/escaped/long paths, audio-only files, zero/unknown length, corrupt/missing/replaced files and unsupported codecs. Show fallback for unsupported input. Verify source changes during extraction never display old-media pixels.
- Timecoded images satisfy the documented bucket/accuracy budget; wrong-start frames and estimated clocks are never reported as verified PTS. Audio-only retains the existing timestamp tooltip. Verify visual aspect, rotation and SDR color; classify HDR limitations explicitly.
- Instrument foreground time/position/state and compare with a no-hover playback control run. Hover must create no seek/control writes, pauses, audio-device changes or visible helper windows. Verify uninterrupted audible playback and absence of additional frame drops/underruns under representative load, including foreground hardware decoding. A private player's software decoding must not change foreground hardware settings.
- Rapid movement, repeated buckets and multiple sliders never exceed one live helper, one pending request and stated cache/IPC bounds. Demonstrate cache hits avoid new decoding. Measure p50/p95 uncached latency before setting a release latency threshold; cache-hit application should fit a normal UI frame. Sustain a rapid-hover stress run and repeated media switches without unbounded memory, handle/process growth or UI hangs.
- Leave/hide/menu/stop/exit removes the preview promptly; late results cannot resurrect it. Preserve click, middle click, drag final-seek, wheel, chapter selection, buffering indication, playback controls, fullscreen transitions and controller auto-hide.
- Test one/two monitors, negative monitor coordinates, mixed 100/150/200% DPI, resizing and screen changes. Keep the complete tooltip on the intended screen without obscuring controls or capturing input. Verify abnormal helper exit, timeout and application shutdown leave no orphaned decoding process.

This stage changes only this architecture document. It does not claim extraction, a modified build or device acceptance has passed.
